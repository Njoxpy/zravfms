---
title: Error Correction
description: Submit receipt error corrections and list correction requests in the VFMS basic API.
---

If you make a mistake on a sale, issue a new, correct receipt first, then submit an error correction request linking the wrong receipt to the new one. Once ZRA approves it, VFMS marks the old receipt and removes it from your invoice list.

## New error correction

- **Endpoint:** `POST http://102.223.7.131:6060/vfms/error-management/new`
- **Header:** `vfms-request-type: ERROR_SAVE`

### Request fields

| Field | Type | Description |
| --- | --- | --- |
| `b_unit_name` | String | Business unit name. |
| `email` | String | Taxpayer email address. |
| `new_receipt_number` | String | The correct (new) receipt number. |
| `old_receipt_number` | String | The receipt issued in error. |
| `phone_no` | String | Taxpayer mobile number. |
| `reasons` | String | Reason for the correction. |
| `unitId` | Long | Business unit ID. |
| `zrb_number` | String | Your ZRB registration number. |

### Request example

```json
{
  "b_unit_name": "RASHID HABIB ALI",
  "email": "taxpayer@example.com",
  "new_receipt_number": "NXM0152",
  "old_receipt_number": "NXM0151",
  "phone_no": "0772724747",
  "reasons": "TEST ERROR",
  "unitId": 38,
  "zrb_number": "Z025608121"
}
```

### Response fields

| Field | Type | Description |
| --- | --- | --- |
| `status` | String | Status code. |
| `statusMessage` | String | Status message. |
| `message` | String | Human-readable message. |

### Response example

```json
{
  "status": 200,
  "statusMessage": "success",
  "message": "Your application has been received, you will be notified once it has been processed."
}
```

A `200` here means the request was received, not approved. Use the report endpoint below to follow its status.

## Error correction report

Lists your error correction requests, filtered by status.

- **Endpoint:** `POST http://102.223.7.131:6060/vfms/error-management/errors/`
- **Header:** `vfms-request-type: ERRORS_MANAGEMENTS`

### Status filter values

| To view | `status` value |
| --- | --- |
| All errors | `0` |
| Pending | `Pendings` |
| Approved | `Approved` |
| Rejected | `Rejected` |
| Under verification | `Verification` |

<Callout type="warn">
  The Basic API guide lists only the status values above and gives no request schema. The [Hotel API](/docs/2) documents a request body of `startDate`, `endDate`, `status` and `unitId` with numeric status codes. Confirm the accepted format against the test environment.
</Callout>

### Response example

```json
{
  "approved": 19,
  "notVerified": 0,
  "totalItems": 51,
  "rejected": 10,
  "errorList": [
    {
      "id_error_taxpayer": 66,
      "old_receipt_number": "NXM0151",
      "new_receipt_number": "NXM0152",
      "reasons": "TEST ERROR",
      "zrb_number": "Z025608121",
      "b_unit_name": "RASHID HABIB ALI",
      "unitId": 6845,
      "status": "Pending",
      "created_at": "2024-01-11T12:19:32.799+03:00",
      "review_date": null,
      "email": "taxpayer@example.com",
      "phone_no": null
    }
  ]
}
```

| Field | Description |
| --- | --- |
| `approved`, `rejected`, `notVerified` | Counts of requests by status. |
| `totalItems` | Total number of requests. |
| `errorList[]` | The requests, each with the submitted fields plus `id_error_taxpayer`, `status`, `created_at` and `review_date`. |
